# 模块接口说明书 · 桌面温控时钟

> 用途：动手写代码之前先把"每个模块对外提供什么"定下来。
> 定完之后，你写任何一个模块时都不用关心别的模块内部怎么实现——这就是分层的意义。

---

## 一、分层与依赖规则

```
        ┌──────────────────────────────┐
        │  User/main.c   调度器          │  按时间片调 Task，路由按键事件
        └───────────────┬──────────────┘
                        │ 只调 App 层
        ┌───────────────▼──────────────┐
        │  App/   Clock  Temp  Menu  Link │  业务逻辑
        └───────────────┬──────────────┘
                        │ 只调 Hardware 层
        ┌───────────────▼──────────────┐
        │  Hardware/  OLED Key Buzzer Fan LM75 LED │  驱动
        └──────────────────────────────┘
```

**四条铁律（违反任何一条，项目就会开始烂）**

1. Hardware 层不许 `#include` 任何 App 头文件，也不许知道"温度""页面"这种词。
2. **只有 Menu 能调 OLED**；main 和 Clock/Temp 直接刷屏会造成两个地方抢屏幕。
3. **只有 Temp 能调 Fan**；别的地方想让风扇转，只能改阈值。
4. 中断里只做"存数据 / 置标志"，解析、判断、显示一律回主循环。

## 三、Hardware 层（已实现，可直接用）

### 3.1 OLED

| 函数 | 参数 | 说明 |
|---|---|---|
| `OLED_Init()` | — | 上电初始化，必须在所有画图之前调 |
| `OLED_Clear()` | — | 清屏 |
| `OLED_ShowChar(Line, Col, Char)` | 行1~4，列1~16 | 单个字符 |
| `OLED_ShowString(Line, Col, *Str)` | | 字符串 |
| `OLED_ShowNum(Line, Col, Num, Len)` | | 无符号，`Len` 是**固定位数**，不够补 0 |
| `OLED_ShowSignedNum(...)` | | 带正负号，占 `Len+1` 列 |
| `OLED_ShowHexNum / ShowBinNum` | | 调试用 |

**不该做**：把 `255` 换算成 `"25.5"`。换算属于 Menu，OLED 只管画。
**坑**：`ShowSignedNum` 正数也会画 `+`，所以它比 `ShowNum` 多占一列，排版面时容易压掉后一个字符。

### 3.2 Key

| 函数 | 调用时机 | 说明 |
|---|---|---|
| `Key_Init()` | 开机 | 配 PA4/PA5/PA6 上拉输入 |
| `Key_Tick()` | **每 10ms** | 扫描 + 30ms 消抖，产生事件 |
| `Key_GetEvent()` | 主循环任意时刻 | 返回 1/2/3，取完自动清零 |

**不该做**：判断"现在在设置页，所以 K2 是加时间"。那是 Menu 的事。

### 3.3 Buzzer

| 函数 | 说明 |
|---|---|
| `Buzzer_Init()` | PA3 推挽输出 |
| `Buzzer_On()` / `Buzzer_Off()` | 直接控制 |
| `Buzzer_Beep(ms)` | **阻塞** ms 毫秒 |

**建议改进（值得做）**：把 `Beep` 改成非阻塞——
```c
void Buzzer_BeepAsync(uint16_t ms);   // 只记时长，立刻返回
void Buzzer_Tick(void);               // 放在 10ms 任务里，到点自动关
```
为什么：现在 `Temp_Task` 每秒报警要 `Beep(100)`，主循环每年卡 100ms，按键会漏。

### 3.4 Fan

| 函数 | 说明 |
|---|---|
| `Fan_Init()` | PA0 / TIM2_CH1，20kHz |
| `Fan_SetSpeed(Percent)` | 0~100，超出自动截断 |

**建议改进**：`Fan_RampTo(目标, 步进)` 做软启动，避免 0→100 的电流冲击把 MCU 拉复位。

### 3.5 LM75

| 函数 | 说明 |
|---|---|
| `LM75_Init()` | PB10/PB11 开漏，软件 I2C |
| `LM75_ReadTemp()` | 返回 **℃×10**（255 = 25.5℃），失败返回 `-999` |

**约定**：所有温度一律用"℃×10 的 int16"，全工程不要出现 float——省空间、不怕打印格式。

### 3.6 LED

`LED_Init / LED_On / LED_Off / LED_Turn`，接 PC13。

**用途**：当**心跳灯**。1Hz 翻转，一眼看出程序有没有卡死。合并项目调试时这一个灯能省你半天。

## 四、App 层（要自己写）

### 4.1 Clock —— 时间从哪来

```c
typedef struct {
    uint16_t year;      /* 2026 */
    uint8_t  month;     /* 1~12 */
    uint8_t  day;       /* 1~31 */
    uint8_t  week;      /* 0=周日 ... 6=周六 */
    uint8_t  hour;
    uint8_t  minute;
    uint8_t  second;
} ClockTime_t;

void    Clock_Init(void);                        /* RTC + LSE + 备份域；只在首次上电设默认时间 */
void    Clock_Task(void);                        /* 每秒调一次：秒/分/时进位，跨天算星期 */
void    Clock_GetTime(ClockTime_t *t);           /* 取当前时间（给 Menu 显示） */
uint8_t Clock_SetTime(const ClockTime_t *t);     /* 0=成功，-1=参数非法 */
uint8_t Clock_SetAlarm(uint8_t hour, uint8_t minute);
uint8_t Clock_CheckAlarm(void);                  /* 1=到点，内部要保证一分钟只返回一次 */
```

**内部要有**：闰年判断、每个月天数表、BCD ↔ 十进制、星期计算（蔡勒公式 10 行）。
**不做**：不碰 OLED、不碰蜂鸣器——到点了只是"返回 1"，响不响由 main 决定。

### 4.2 Temp —— 温度准不准，风扇开不开

```c
void    Temp_Init(int16_t OnX10);        /* 输入开风扇阈值，如 280 = 28.0℃ */
void    Temp_Task(void);                 /* 每秒调一次：采样→滤波→迟滞判断→Fan_SetSpeed */
int16_t Temp_GetValue(void);             /* ℃×10，给 Menu 显示 */
uint8_t Temp_GetFan(void);               /* 当前风扇百分比 0~100 */
void    Temp_SetThreshold(int16_t OnX10);
uint8_t Temp_IsAlarm(void);              /* 超高温标志，给 main 决定响不响 */
```

**内部要有**：
- 连续 4 次滑动平均（LM75 有 ±0.5℃ 跳动，不滤波风扇会抖）
- 读失败（-999）时保持上一次的值
- 迟滞：`>= On` 开，`<= On - 20` 才关
- 风扇分档：超过 30.0℃ 给 100%，否则 60%

**不做**：不显示，不判断页面。

### 4.3 Menu —— 按键什么意思，屏幕画什么

```c
typedef enum { PAGE_MAIN, PAGE_SET, PAGE_ALARM, PAGE_STOPWATCH, PAGE_COUNT } Page_t;

void   Menu_Init(void);
void   Menu_KeyEvent(uint8_t event);   /* 按键语义在这里解释：同一个 K2 在不同页做不同事 */
void   Menu_Render(void);              /* 画当前页面：事件后 + 每秒一次 */
Page_t Menu_GetPage(void);
```

**这是整个项目"协调"的核心。** 建议的语义表：

| 页面 | K1 | K2 | K3 |
|---|---|---|---|
| MAIN 主页 | 进设置 | 切闹钟页 | 手动开/关风扇 |
| SET 设置 | 切换字段（时→分→阈值） | + | − |
| ALARM 闹钟 | 返回 | 时+ | 分+ |
| STOPWATCH | 返回 | 开始/暂停 | 清零 |

**内部要有**：当前页面、当前编辑字段（靠闪烁提示）、渲染时只读别的模块的 `Get` 接口。

### 4.4 Link（可选）—— 串口

```c
void Link_Init(void);                 /* USART1 + 环形缓冲 + 接收中断 */
void Link_Task(void);                 /* 100ms 调一次：解析完整帧 */
void Link_SendTemp(int16_t t);        /* 每秒上报 */
```

`USART1_IRQHandler` 里只做一件事：把字节塞进环形缓冲区。
**坑**：在中断里 `printf` 或比较字符串，会丢数据甚至死机。

## 五、调用频率总表（写在 main.c 里就是调度器）

| 周期 | 调谁 | 说明 |
|---|---|---|
| 1ms | `TIM3_IRQHandler` | **只置标志位**，一行逻辑都别加 |
| 10ms | `Key_Tick()` + `Buzzer_Tick()` | 消抖、蜂鸣器计时 |
| 100ms | `Link_Task()`（可选） | 串口解析 |
| 1000ms | `Clock_Task()` → `Temp_Task()` → `Menu_Render()` | 业务 + 刷新 |
| 事件驱动 | `Menu_KeyEvent(ev)` | 按键立刻响应，不等 1 秒 |
| 1s | `LED_Turn()` | 心跳 |

**顺序有讲究**：先 `Clock_Task` 再 `Temp_Task`（时间先更新，显示才是新的）；`Menu_Render` 永远最后（画的是别人算好的结果）。

## 六、数据怎么流

```
LM75 ──读──> Temp.Temp10 ──决策──> Fan_SetSpeed
                    │
                    └──Get──> Menu ──画──> OLED
RTC  ──读──> Clock.t ──Get──> Menu ──画──> OLED
Key  ──事件──> main ──转发──> Menu ──Set──> Clock / Temp
```

**关键点：数据是单向流动的。** Menu 只是"读"和"转发命令"，它自己不存温度、不存时间。这样任何一个数字显示错了，你只需要查一个来源。

## 七、现在工程的实际情况

`User/main.c` 目前把 Clock / Temp / Menu 的逻辑**内联在同一个文件里**（`Clock_Task`、`Temp_Task`、`Display_Main`、`Key_Handle`）。这是故意的：先跑通，再拆。

拆的顺序建议：

1. 先把 `Temp_Task` + `LM75` 相关搬进 `App/Temp.c`（最独立，最好拆）
2. 再把 `Clock_Task` 换成真正的 RTC，搬进 `App/Clock.c`
3. 最后拆 `Menu.c`——它要拿到前两个的 `Get` 接口才拆得动
4. `main.c` 最后只剩初始化 + 五条调度语句，大约 40 行

## 八、命名与单位约定

| 约定 | 例子 |
|---|---|
| `模块_动作` | `Temp_Task`、`Menu_Render` |
| 值是 10 倍的，后缀加 `X10` | `OnX10`、`Temp10` |
| 返回 0 成功 / -1 失败 | `Clock_SetTime` |
| 读失败用特殊值，不用 0 | `LM75` 返回 `-999` |
| 全局变量加模块前缀 | `Temp_Value`、`Clock_Time` |
