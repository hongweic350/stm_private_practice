# 实战项目1 · 桌面温控时钟（电子钟 × 温控 合并版）

> 文件夹名沿用了旧的 `实战项目1-桌面智能温控`（改名时被 Keil 占用），内容就是下面这个合并版。

桌面上放一个东西，同时干两件事：**显示时间** + **显示室温并自动开风扇降温**。
没有 PID，没有机械结构，一根 USB 供电（风扇另外 5V），约 55 元。

> 定位：`实战项目3-桌面电子钟` 是它的拆解版（每天一个独立小练习）；
> 这个项目是**综合版**——同样的外设，加上"多个任务抢一个屏幕、一个主循环"的调度问题。

---

## 一、合并到底"综合"在哪

新手容易以为"综合 = 功能多"。不是。真正的综合是这三件事：

| 资源 | 时钟那边要 | 温控那边要 | 合并后的解法（这才是要学的） |
|---|---|---|---|
| 一块 OLED | 显示日期时间 | 显示温度、风扇档位 | **分页面**：主页合并显示，设置页单独 |
| 一个主循环 | 每秒刷新 | 每秒采样 | **时间片**：10ms 扫按键 / 1000ms 跑业务 |
| 一套按键 | 调时、调日期 | 调阈值 | **按键语义随页面变化**，同一个 KEY2 在两个页面干两件事 |
| 一个定时器 | 1ms 节拍 | 1ms 节拍 | 共用 TIM3，只置标志位，不在中断里干活 |
| 一根串口 | 校时 | 上报温度 | 一张命令表，两种命令共用一个协议帧 |

如果只是把两份代码用 `if` 拼起来，那不叫综合，叫堆砌——**而且会死**：`Delay_ms` 一多，时钟就不准、按键就不灵。

## 二、合并的收益与代价

**收益**
- 外设覆盖一次到齐：RTC / I2C（两种设备）/ PWM / TIM 中断 / ADC / USART / 按键状态机
- 一个能一直摆在桌面上用的东西，比"跑完就拆"的 demo 有成就感
- 逼你学会**非阻塞编程**——这是从"照抄教程"到"自己写项目"的分水岭

**代价**
- 调试面积变大：出问题时可能是任何一个模块 → 所以**必须先分模块验证**，别一上来就合并
- 显示要分页面，代码量比单个项目多约 40%
- 供电：风扇能吃 100~200mA，USB 口够；**但加热器绝对不够**，别想着做"加热+制冷"

## 三、物料（约 55 元）

| 主控 | STM32F103C8T6 最小系统板 | 15 | 已有 |
| 显示 | 0.96" I2C OLED | 10 | 已有 |
| 温度 | **LM75A 模块**（I2C） | 4 | 别用 DS18B20，单总线时序对新手太劝退 |

| 驱动 | S8050 / AO3400 + 1kΩ + 1N4148 续流二极管 | 3 | MOS 管更好，发热小 |
| 按键 | 轻触开关 ×3 | 2 | |
| 蜂鸣器 | 有源蜂鸣器 + S8550 + 1kΩ | 3 | |

**为什么只做降温不做加热**：加热要 5V×1A 以上，USB 口带不动，还容易把板子烤了。降温用风扇，逻辑一样（阈值 + 迟滞），风险为零。

## 四、接线表

| 功能 | 引脚 | 说明 |
|---|---|---|
| OLED SCL / SDA | PB8 / PB9 | 软件 I2C（模板自带） |
| LM75A SCL / SDA | PB10 / PB11 | 另一条软件 I2C，地址 0x48 |
| 风扇 PWM | PA0 | TIM2_CH1，20kHz，经 MOS 管 |
| 按键 K1 / K2 / K3 | PA4 / PA5 / PA6 | 内部上拉 |
| 蜂鸣器 | PA3 | 经三极管 |
| 串口 TX / RX | PA9 / PA10 | USB-TTL，调试用 |

> 两条 I2C 总线不冲突，正好练一次"同一套 I2C 时序驱动两个不同器件"。

## 五、代码结构（空白工程，由你填）

> 每个模块对外应该提供哪些函数、参数怎么定、谁调谁，见 [`docs/模块接口.md`](docs/模块接口.md)。

```
Hardware/
  OLED.c/h     模板自带（唯一保留下来的驱动）
  LED.c/h      模板自带（可当心跳灯）
User/main.c    只有 OLED_Init() + 一个空 while
```

**工程已清空**：Key / Buzzer / Fan / LM75 全部删掉了，连 `main.c` 里的调度骨架也一起删了——这些是你要自己写的部分。
照着 `docs/模块接口.md` 里的函数签名一个一个填，先写驱动，再写调度，最后写业务。

自己写的时候，目标形态是这样：

```c
TIM3 每 1ms 中断 -> 只置标志位（10ms / 1000ms）
主循环：
    Flag_10ms   -> Key_Tick()        按键扫描，不阻塞
    Flag_1000ms -> Clock_Task()      走时
                   Temp_Task()       采样 + 迟滞判断 + 风扇
                   Menu_Render()
    随时        -> Key_GetEvent()    有事件立刻响应
```

## 六、阶段任务

| 阶段 | 做什么 | 验收 | 时间 |
|---|---|---|---|
| 0 | 逐个模块自检：OLED 出字、按键有事件、蜂鸣器响、风扇 0/50/100% 三档、LM75 读数 | 五个模块单独都能工作 | 2h |
| 1 | 搭 1ms 节拍 + 时间片调度，时间先用软件计数器顶着 | 秒在走，按键切页不卡顿 | 1h |
| 2 | LM75 接上，主页显示真实室温 | 和温度计差 < 1℃ | 1h |
| 3 | **RTC 替换软件计数器** | 拔电重插，时间继续走 | 2h |
| 4 | 温控：调阈值，看风扇自动启停 | 手捂传感器，风扇能开能关，不来回抖 | 1h |
| 5 | 闹钟 + 整点报时 | 到点响，任意键停 | 1h |
| 6 | 串口：`TIME 2026-10-19 12:00:00` 校时；每秒上报温度 | 上位机看到曲线 | 2h |
| 7 | 加分：阈值存 Flash/BKP、IWDG、低功耗待机、外壳 | | |

**阶段 0 是硬要求**：合并项目最常见的死法，就是五个模块里有俩是坏的，然后你在主循环里同时调五个东西。

## 七、这个项目特有的坑

1. **迟滞不能省**：`TEMP_ON` 和 `TEMP_OFF` 之间至少留 1~2℃。否则温度在阈值上下抖动时，风扇会"哒哒哒"反复启停，继电器/风扇都受不了。
2. **I2C 读失败不要当成 0℃**：`LM75_ReadTemp()` 失败返回 `-999`，要"保持上一次的值"，否则一次干扰就让风扇全开。
3. **风扇要续流二极管**：电机断电瞬间反向电动势会打穿 MOS 管、干扰 MCU（表现是屏幕花一下、程序复位）。
4. **别在中断里刷 OLED**：I2C 一次刷屏几毫秒，放中断里会把 1ms 节拍挤爆。
5. **两个软 I2C 不要共引脚**：分两条总线，省得以后改一处崩两处。
6. **按键事件要在主循环取**：在定时器中断里取事件，容易丢——`Key_GetEvent()` 只做"读并清零"。

## 八、完成标准

连续插电 24 小时：时间误差 < 5 秒、温度显示正常、手捂传感器风扇能开、松手能关、按键随时响应不卡顿。

做到这个，基础篇的外设你就算真的会用了——**因为这时候你已经不是在"调外设"，是在"管一个系统"**。
