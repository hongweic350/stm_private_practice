# 实战项目1 · 桌面温控时钟

STM32F103C8T6 + DHT11 + 0.96" OLED + W25Q64 的桌面小系统：**测室温、自动开风扇、看时间、查历史最值**。
一块屏、两个按键、一个主循环，三个页面轮着用。

> 本文描述的是**当前代码的实际状态**（`User/main.c` 与 `Hardware/` 下的驱动），不是最初的任务规划。
> 最初的功能拆解与验收标准见 [`docs/模块接口.md`](docs/模块接口.md)。

---

## 一、现在能做什么

三个页面，**K1 = 下一页，K2 = 上一页**，循环切换：

| 页面 | 屏幕内容 | 数据来源 |
|---|---|---|
| **0 · 温湿度** | `humidity: 45.3` / `heat: 26.7` | DHT11（PA0 单总线），每 1.5 s 采样 |
| **1 · 时钟** | 年 / 月 / 日 / 时 / 分 / 秒 | 片内 RTC |
| **2 · 最值** | 本次上电以来湿度、温度的最大值与最小值 | W25Q64 里的历史记录 |

后台同时做两件事：

- **控温**：温度 ≥ 27.0 ℃ → 风扇 PWM 输出 50%；低于 → 0%。
- **记录**：每次有效采样写 5 字节进 W25Q64（湿度整数、湿度小数、温度整数、温度小数、校验和）。

## 二、硬件与接线

| 功能 | 引脚 | 外设 / 模式 | 备注 |
|---|---|---|---|
| OLED SCL | **PB8** | 软件 I2C（开漏） | 从机地址 `0x78` |
| OLED SDA | **PB9** | 软件 I2C（开漏） | |
| DHT11 DATA | **PA0** | 单总线（软件时序） | 数据线需 4.7k~10k 上拉 |
| 风扇 PWM | **PA1** | TIM2_CH2，复用推挽 | 1 kHz，经 MOS/三极管驱动 |
| 按键 K1 | **PB12** | GPIO 输入下拉 | 按下为高 → 下一页 |
| 按键 K2 | **PB15** | GPIO 输入下拉 | 按下为高 → 上一页 |
| W25Q64 CS | **PA4** | GPIO 推挽 | 软件片选 |
| W25Q64 SCK | **PA5** | SPI1 | 562.5 kHz（72 MHz / 128） |
| W25Q64 MISO | **PA6** | SPI1 | 上拉输入 |
| W25Q64 MOSI | **PA7** | SPI1 | |

- 主控：STM32F103C8T6 最小系统板，72 MHz，标准外设库（无 HAL / CubeMX）
- 存储：W25Q64（8 MB SPI Flash），只用了**扇区 0 的前 4 KB**
- 供电：USB 5 V；风扇单独接 5 V，**电机的续流二极管不能省**

## 四、主循环怎么跑

```c
while (1)
{
    Key_GetNum();                       // 阻塞：按下后等松手才返回 1/2

    if (换页) { 清屏; 画标题; }          // DrawFlag 只在换页时置 1

    if (Mode == 0)                      // 温湿度页
    {
        if (Tick == 0)                  // 每 30 个节拍 = 1.5 s 采一次
        {
            DHT11_ReadData(Data);       // 失败返回 0 = 无应答
            校验 Data[4] == Data[0..3] 之和;
            有效 -> 显示;  >= 27.0 ℃ ? 风扇 50% : 0;  写 Flash
            无效 -> 显示 "Data wrong"
            无应答 -> 显示 "No Ack"
        }
    }
    else if (Mode == 1) 读 RTC 并刷新年月日时分秒;
    else                从 Flash 地址 0 扫到第一片 0xFF，算最大/最小;

    Delay_ms(50);  Tick++;
    if (Tick >= 30) Tick = 0;
}
```

三个设计点：

1. **页面用 `Mode` 变量记住**，不依赖"按键此刻是否按下"，松手后不会跳回上一页。
2. **`DrawFlag` 把"清屏 + 画标题"和"刷新数值"分开**，避免每帧重画导致闪屏。
3. **`Tick` 是软节拍**：`Delay_ms(50)` 循环 30 次凑 1.5 s，采样间隔和其他页面解耦。

## 六、编译与下载

1. 用 Keil MDK 打开 `Project.uvprojx`，器件已选 `STM32F103C8`
2. 依赖 `USE_STDPERIPH_DRIVER`，`Library/` 自带标准外设库，不需要额外 Pack
3. 编译后通过 ST-Link / DAP-Link（SWD 四线）下载
4. 工程里 **`Create HEX File` 是关闭的**，只生成 `.axf`；需要 hex 就在 *Options → Output* 勾上

**首次上电的三件事**：

- 开头 `Delay_ms(1000)` 是为了等 DHT11 稳定，避免第一帧脏数据被显示和记录
- 上电会**擦除 W25Q64 扇区 0**，所以"最值页"的数据每次重启清零
- 板子没焊 32.768 kHz 晶振时，`MyRTC_Init` 等 3 秒后自动切到内部 LSI，走时误差会明显变大

## 七、已知问题（下一版要改的）

1. **风扇没有迟滞**：温度在 27 ℃ 上下抖动 0.1 ℃ 就会反复开关。应改成"≥27.0 开、≤25.5 关"。
2. **最值页每次都重扫整个 Flash**：一边读 SPI 一边算，819 条扫完页面会明显卡顿；应该开机扫一次、缓存结果。
3. **`Key_GetNum()` 是阻塞的**：`while(引脚为高)` 等松手，按住不放时整个系统停摆（时钟不走、不采样）。应改成定时扫描 + 事件标志。
4. **`Delay_ms(50)` 当节拍不准**：Mode 1 读 RTC 刷屏、Mode 2 扫 Flash 的耗时会叠加进节拍，实际周期比 1.5 s 长。
5. **负温度算错**：DHT11 温度小数在零下时含义不同，当前统一按"整数 + 0.1 × 小数"计算。
6. **`LED.c` 与风扇抢 PA1**：`LED_Init()` 会把 PA1 配成推挽输出，直接打断 PWM。当前 `main.c` 没有调用它，别加回去；LED 实际可用 PA2。
7. **串口功能未做**：设计里的 USART 校时 / 温度上报还没实现。
